🔹 Virtual Environment in Python
    A virtual environment is an isolated Python workspace that allows you to install and manage project-specific 
    libraries without affecting the global Python installation.

    It helps avoid dependency conflicts when working on multiple Python projects on the same machine.

🔹 Why Do We Need Virtual Environments?
    Imagine:
    * Project A needs Django 3.2
    * Project B needs Django 4.2

    Installing both globally would cause conflicts.
    A virtual environment solves this by creating separate environments for each project.

🔹 Benefits of Virtual Environment:
    ✅ Isolates project dependencies
    ✅ Prevents version conflicts
    ✅ Keeps global Python clean
    ✅ Makes projects portable and reproducible
    ✅ Industry best practice

🔹 Creating a Virtual Environment:
    Python provides the built-in venv module.

    🔸 Create a virtual environment:
        python -m venv myenv

    This creates a folder myenv containing:
    * A private Python interpreter
    * Local site-packages
    * Activation scripts

🔹 Activating the Virtual Environment:

    🔸 On Linux / macOS:
        source myenv/bin/activate

    🔸 On Windows:
        myenv\Scripts\activate

    Once activated, you’ll see:
        (myenv)

    before your terminal prompt.

🔹 Installing Packages Inside Virtual Environment:
        pip install numpy
        pip install flask

    📌 These packages are installed only inside the virtual environment, not globally.

🔹 Deactivating the Virtual Environment:
        deactivate

    This switches you back to the global Python environment.

🔹 pip freeze -> this command will give the list of all installed libraries or packages of venv in the terminal    

🔹 requirements.txt File
    A requirements.txt file stores a list of all project dependencies with their versions.

    Example:
        flask==2.3.2
        numpy==1.26.0
        requests==2.31.0

🔹 Creating requirements.txt
    Use pip freeze:
        pip freeze > requirements.txt

    This records exact package versions, ensuring consistency across machines.

🔹 Installing from requirements.txt
        pip install -r requirements.txt

    This installs all required packages at once.

🔹 Why requirements.txt Is Important?
    ✔ Easy project setup
    ✔ Same environment for all developers
    ✔ Useful for deployment and CI/CD
    ✔ Required in real-world projects

🔹 Virtual Environment Workflow (Recommended)
    Create venv → Activate → Install packages → Develop → Freeze requirements → Share project

📝 Interview One-Liner 💡
    A virtual environment in Python is an isolated environment that allows project-specific dependency management without 
    interfering with the global Python setup.

🔹 Common Interview Questions
    
    Q. Is venv built-in?
        ✔ Yes, available from Python 3.3+

    Q. Does pip install globally inside venv?
        ❌ No, only inside that environment

    Q. Can one system have multiple virtual environments?
        ✔ Yes, unlimited
