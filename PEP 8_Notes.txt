🔹 PEP 8 – Python Style Guide

What is PEP 8?
    PEP 8 is the official style guide for Python code.
    It provides rules and best practices to write clean, readable, and consistent Python programs.

📌 PEP stands for Python Enhancement Proposal

🔹 Who wrote PEP 8?
    PEP 8 was written in 2001 by:
    * Guido van Rossum (creator of Python)
    * Barry Warsaw
    * Nick Coghlan

🔹 Why PEP 8 is Important?
    * Improves code readability
    * Makes code consistent across teams
    * Helps in collaborative development
    * Preferred in interviews and real projects

💼 Interview Tip:
    Clean code matters as much as correct code.    

🔹 What is a PEP?
    * A PEP (Python Enhancement Proposal) is a document that:
    * Proposes new Python features
    * Describes design decisions
    * Defines coding standards and styles

📌 Example PEPs:
    * PEP 8 → Code style
    * PEP 20 → Zen of Python
    * PEP 484 → Type hints  

🔹 Key PEP 8 Guidelines (Must-Know):

1. Indentation
    * Use 4 spaces per indentation level
    * Do not use tabs

        if x > 0:
            print("Positive")

2. Line Length
    * Maximum 79 characters per line
    * For comments: 72 characters  

3. Naming Conventions

| Element  | Convention                 | Example           |
| -------- | -------------------------- | ----------------- |
| Variable | lowercase_with_underscores | `total_count`     |
| Function | lowercase_with_underscores | `calculate_sum()` |
| Class    | CamelCase                  | `StudentRecord`   |
| Constant | UPPERCASE                  | `MAX_LIMIT`       |

4. Spaces Around Operators
        # Good
        x = y + 5

        # Bad
        x=y+5

5. Blank Lines
    * Use 2 blank lines between top-level functions and classes
    * Use 1 blank line between methods

6. Imports
    * One import per line
    * Standard imports first, then third-party, then local

        import os
        import sys    

🔹 What is the Zen of Python?
    It is a collection of 19 guiding principles that describe Python’s design philosophy, focusing on simplicity, 
    readability, and explicitness.

🔹 The Zen of Python (PEP 20)
    The Zen of Python describes Python’s design philosophy.
    It was written by Tim Peters.      

🔹 How to View the Zen of Python (Easter Egg 🥚)
        import this 

🔹 Zen of Python – Important Principles (Interview Gold ⭐):

    Beautiful is better than ugly → Code should look clean and well-structured.
    Explicit is better than implicit → Be clear; don’t rely on hidden behavior.
    Simple is better than complex → Prefer simple solutions.
    Complex is better than complicated → Some complexity is okay, confusion is not.
    Flat is better than nested → Avoid deep nesting.
    Sparse is better than dense → Use spacing for readability.
    Readability counts → Readable code is more important than clever code.
    Special cases aren’t special enough to break the rules → Follow conventions.
    Although practicality beats purity → Practical solutions matter.
    Errors should never pass silently → Handle errors properly.
    Unless explicitly silenced → Ignore errors only when intentional.
    In the face of ambiguity, refuse the temptation to guess → Avoid unclear logic.
    There should be one obvious way to do it → Prefer standard solutions.
    Although that way may not be obvious at first unless you're Dutch → Humor about Python’s creator 😄
    Now is better than never → Don’t delay unnecessarily.
    Although never is often better than right now → Don’t rush bad code.
    If the implementation is hard to explain, it's a bad idea → Complexity = bad design.
    If the implementation is easy to explain, it may be a good idea → Simplicity wins.
    Namespaces are one honking great idea → Use modules, classes, scopes.

📌 Total aphorisms: 19 written, 20 intended

❓ Why only 19?
    Tim Peters originally intended 20 aphorisms, but only 19 were written down.
    The missing 20th is an intentional mystery 😉

📘 PEP 8 vs Zen of Python (Very Important):

| PEP 8                               | Zen of Python                   |
| ----------------------------------- | ------------------------------- |
| Coding **style guide**              | Coding **philosophy**           |
| How to write code                   | Why Python is designed this way |
| Covers indentation, naming, spacing | Covers readability & simplicity |
| Enforced by linters                 | Conceptual guidelines           |
| Example: 4-space indentation        | Example: Readability counts     |
